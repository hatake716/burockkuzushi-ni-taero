# 実装仕様 1.0.0

## 仕様の確定

依頼文のスロット周期には５秒と７秒の記載があったため確認し、ユーザー回答により**７秒**に確定した。
玉数リセットは初期値１玉へ戻す。分裂は１玉が２玉になるため、１回のブロック衝突につき子を１玉追加する。
貫通と分裂の重複は、既に有効な残り時間へ５秒追加する形で実装した。

## ゲームループと時間

Android `SystemClock.elapsedRealtimeNanos()` による単調増加クロックを入力とする。
画面フレームごとの実経過ナノ秒を渡し、遅いフレームでも経過時間を切り捨てない。
物理の計画区間は最大４ms。スロット境界・効果の失効境界でも区間を分割する。
各区間では全玉の次の衝突時刻を比較し、最も早い衝突から順番に処理する。
最後のブロックが消える接触時刻で終了し、その後のフレーム残余は加算しない。

ランキング保存単位は100μs（0.0001秒）。`ticks = elapsedNanos / 100000`。
スコアは `BigInteger(ticks)² / 10⁸` を `BigDecimal` で求めるため、整数乗算の桁あふれと浮動小数点の順位ずれを避ける。
スコア表示は小数４桁、切り捨て。順位は生存tickの降順、同点は達成日時の早い順。
小数４桁は保存・表示の分解能を示し、Androidの画面更新や入力・物理計算が10,000Hzで動くという意味ではない。

## 衝突とCPU

- 固定論理座標：幅800×高さ1050。表示側で等比拡大縮小し、端末間の物理条件を揃える。
- 玉の半径７、初速440論理単位/秒。速度効果は全玉に共通の乗算係数で、新しい玉にも適用。
- パドル幅126、最大速度4200論理単位/秒。パドルは毎区間、目標へ速度上限を守って平行移動。
- CPUは下降中の玉の到達時刻と壁反射後の到達位置を予測し、間に合う玉のうち最も早いものを選ぶ。
- ブロックの矩形を玉の半径で広げた領域とのswept collisionを使用。高速玉のトンネリングを防ぐ。角は半径拡張矩形による近似。
- 玉同士の物理衝突はない。
- パドル反射は残存ブロックを狙う。孤立ブロックに届かない定常軌道による長い停滞を避ける。
- 回収できずに全玉が落ちた場合、0.65秒後に現在の速度・効果を保って１玉を再発射する。
- 玉数・速度倍率を密かに切り詰めない。極端な長時間増殖での端末性能は有限であり、無制限の処理性能を保証するものではない。

## 入力

タッチはDOWN時に候補を保持し、同じセル上でUPした時に１個再生する。
途中の複数ポインター検出は候補を破棄し、ゲーム時間で３秒のロックを設定する。
２本目が入った時点で１本目による再生も未確定なので、同時再生の抜け道を作らない。
ロック中に始まった操作・キャンセルされた操作・25論理単位以上動いたドラッグは再生しない。
警告中の追加ポインターで警告終了時刻は延長しない。

## ライフサイクルと保存

- タイトル→開始→３秒の合図→プレイ→全滅→結果→再挑戦またはランキング。
- プレイ中の戻る操作、フォーカス喪失、バックグラウンド移行で一時停止。
- 一時停止中は経過時間・警告残時間・スロット周期・特殊効果を含めて凍結。
- 再開の合図中も生存時間を加算しない。
- ゲーム状態をローカル保存。Activity再生成・プロセス再起動後はタイトルに「つづきから耐える」を表示。
- 終了時にランキングの更新と中断データ削除を同一の同期保存トランザクションで行う。
- ゲームIDによる重複排除。上位100件を越える低い記録は保持しない。
- BGM・SEはバックグラウンドで停止。別アプリへのオーディオフォーカス移行でも一時停止する。
