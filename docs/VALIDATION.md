# 検証記録

検証日：2026-09-13。バージョン1.0.0 / versionCode 1。
パッケージ：`io.github.hatake716.taero`。

## ビルド

JDK 17、Android SDK 36、Gradle 8.14.3、AGP 8.13.0、Kotlin 2.2.20。

```sh
./gradlew testDebugUnitTest lintDebug lintRelease assembleDebug assembleRelease bundleRelease assembleDebugAndroidTest
```

すべて成功。Debug / Release Lintはエラー０、警告31。
警告は依存ライブラリの新バージョン、targetSdk更新提案、縦画面固定、バックアップ設定、KTX・翻訳形式など。
初回に検出したAPI 26で使用できないナビゲーションバー属性は修正済み。

## ロジックテスト

28件成功、失敗・エラー・スキップ０。

- ８×５グリッド、破壊済みセルだけの再生。
- UP時の単指確定、マルチタッチ時に最初の指の候補も取り消す。
- 3.0000秒での警告終了、警告中の物理進行、警告開始中のタッチを後で流用できないこと。
- 7.0000秒でのスロット確定、長いフレームで複数の確定境界を処理すること。
- 速度倍率の乗算、玉数と速度の独立したリセット。
- 貫通・分裂の残時間加算と失効、１玉→２玉の分裂。
- 729倍速でもブロックを通り抜けない連続衝突判定。
- 最後の衝突時刻で終了、複数の玉の処理がリスト順に依存しないこと。
- CPUの移動速度上限、壁反射の予測、両端へ同時落下する玉の取りこぼし。
- 全玉落下後の再発射、スコアの高精度計算、フレーム間の端数保持。
- 100件のランキング切り詰め、同点順序と重複排除。
- 12種類の乱数シードで有限な状態を保ってゲーム終了まで進むこと。

## Android操作テスト

Android 15 / API 35 / x86_64 / 1080×2400の専用エミュレーター `emulator-5554` で10件成功。
実際のMotionEvent複数ポインター入力とUI Automator操作を使用した。

1. 遊び方・音と演出の表示、BGM設定の保存。
2. タイトルから開始、３秒のカウントダウン、実進行、一時停止中の時間停止。
3. 単指のDOWNでは再生せず、UPで指定した１セルだけを再生。
4. 実際の２本指入力で両セルを再生せず、３秒後の単指操作を受け付ける。
5. 空きセルを横断するドラッグでは再生しない。
6. ACTION_CANCELによる候補破棄と、その後の正常なタップ。
7. ７秒の境界でスロット効果を適用する。
8. Activity再生成後に盤面・倍率・警告残時間を復元する。
9. 最後のブロック破壊→結果画面→ランキング保存と表示、重複登録なし。
10. 105件から上位100件が別の保存インスタンスでも読み出せる。

テスト用の特殊な盤面・経過時間はテストコード内だけで設定する。製品にデバッグ操作やチート起動パラメーターは設けていない。
連続描画に対して通常の「画面が静止するまで待つ」処理が停止するため、テストは個別状態を条件に待機する。
タイトルは約12.5fpsの控えめな環境アニメーションにし、一時停止・結果画面の継続再描画を止めた。

## 通常プレイの実表示

通常の開始ボタンからプレイし、スコアと時間、ブロック破壊、CPU移動、７秒ごとのスロット通知、全滅から結果画面までを確認。
再生操作を行わない１回の実行では35.8107秒、1,282.4062pt、CPU効果５回で終了した。
これは１回の乱数結果であり、平均的な難易度・生存時間を示すものではない。

## 音源

同梱BGMは44.1kHz・２チャンネル・42.666667秒。
Vorbisのデコード後にFFmpegで確認した平均音量は-13.2dB、最大-0.5dB。
元のPCMは0.89ピークへ正規化し、BGM再生音量は0.48に設定。
BGM＋５つのSEをAPKに同梱。端末スピーカーでの聴感・音量バランスのユーザー確認は未実施。
